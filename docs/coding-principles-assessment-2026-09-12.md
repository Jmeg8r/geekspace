# Geekspace coding assessment — 2026-09-12

## Scope and baseline

Assessed main `49017e80323de7dfb994345f0fc7e492fe94ae94` in an isolated `fix/coding-principles-geekspace` worktree. The private repository has no forks or collaborators; this is a correctness and runtime-boundary review for its trusted owner. Imported documents, links, model output, malformed client requests and interrupted I/O remain relevant inputs. No hostile-PR-author scenarios were treated as blockers.

The primary checkout was clean. Recorded its HEAD, index, status, existing worktree registration and Git configuration before changes. The assessment does not operate on the real `.convex` workspace, user application data, microphone, Calendar/Mail, AI providers or model runtime. The implementation plan was written before refactoring.

Coverage includes the renderer/editor, recording and meeting pipeline, Convex schema/mutations/relations/scheduler, page lifecycle, project/sprint/templates, Electron IPC/navigation/file/process boundaries, both agent lanes and MCP, optional knowledge/reader bridges, migration and packaging helpers, dependencies and CI. This is a domain-oriented code assessment with targeted runtime tests, not an exhaustive formal audit or a native release qualification.

## Findings and changes

1. **Data preservation:** migration replaced a fixed `.bak`, and first-launch seeding copied over an existing directory if its config was missing. Shared filesystem primitives now validate the source, stage the copy, reject partial existing data, preserve uniquely named backups, and refuse factory initialization when an interrupted migration left a backup. The migration command refuses a listener on the standard backend port. Packaging fails if its required backend binary is absent.
2. **Relations and mutation atomicity:** creation omitted reverse relation writes; row deletion left inbound references; deleting a self-relation left its reverse property. A shared transactional row writer validates domain values and relation targets, updates both sides, and supports one atomic MCP property batch. Deletion clears inbound row relations and time blocks. Property removal clears both definitions and values. Existing malformed data is not rewritten automatically.
3. **Scheduling:** locked future work was counted as busy time but not deducted from its task estimate, producing duplicate allocations. Pinned work now counts once; dependents respect reserved blocker end times, and partially scheduled blockers do not count as finished. Invalid/non-finite hours, chunks, horizon, granularity, timezone and event ranges fail before mutation. Long overlapping appointments are included. Property changes/removal, permanent page deletion and sprint completion reflow the schedule. Task-source edits retain the PM mapping fields.
4. **Boundary validation:** row values, view types/filters/sorts, option definitions and number/rollup formats have concrete input validators. Template start dates are bounded calendar dates; ambiguous duplicate task titles fail instead of silently rebinding dependency chains.
5. **Editor recovery:** saves are serialized and failed writes retain the newest edit for retry. Edits are also retained per document in local storage before debounce; reopening offers explicit draft recovery or keeping the server version. An older save cannot clear a newer draft. Malformed stored content is preserved and displayed for recovery instead of replaced by a blank document. Title editors remount per document, flushing the previous title's debounce. Backend shutdown waits until windows accept closing, keeping it available while a save guard blocks closing.
6. **Recording lifecycle:** failed setup closes the opened microphone; a pending start blocks concurrent starts and can be cancelled safely. Late permission grants are closed after cancellation. Concurrent stop attempts are rejected and hardware is released on stop failure. Reprocessing HTTP failures are reported on the meeting; UI catches failed operations. Regenerating AI notes preserves manually edited pages by creating a new generated page when the original has diverged.
7. **Electron boundaries:** only the actual application entry page and its main frame can invoke privileged handlers. Window creation/navigation no longer accept arbitrary file URLs or prefix lookalikes; external protocols are restricted, webviews disabled, sandbox explicit and media permissions limited to the trusted window's audio requests. Storage hand-off validates exact origin/path, rejects redirects, bounds downloads at 64 MiB, uses private temporary files, restricts executable file types, and checks `shell.openPath` failures. Text previews stream a bounded prefix and clear stale state between files.
8. **Agent and MCP behavior:** `allowedTools` was an automatic-permission list, not an exclusive tool set. Claude now disables built-ins, skills and external configuration, uses only the supplied MCP server, and applies an explicit workspace-tool permission handler. The UI selects cloud processing explicitly and explains its data flow; error frames are visible. Local requests have deadlines and an unavailable explicitly configured model fails instead of selecting a different model. MCP's Zod 4 record schemas now work, date parsing rejects calendar overflow, booleans are strict, and multi-property edits use one mutation.
9. **Calendar and file integrity:** incomplete Calendar reads abort the sync instead of deleting missing mirrors. Overlapping events are fetched, and Mail failures no longer masquerade as an empty inbox. Whisper model downloads use unique temporary files, a shared in-flight request, bounded HTTPS redirects/time, exact length and SHA-256 verification before publication. A same-size corrupt file is rejected. Deployment credentials use a private temporary directory/file.
10. **Dependencies and CI:** compatible updates and aligned Tiptap 3.31.3 overrides remove the reported vulnerabilities. Convex stays at 1.41.0 to preserve the bundled backend contract, with compatible `ws` 8.21.3 overridden. CI additionally builds the renderer and audits the lockfile. Deployed gate copies and their coverage limits are unchanged.

## Acceptance and operational limits

No merge, deployment, real data migration, seed/prebake run, model download/load, provider request, microphone capture or Calendar/Mail operation occurred. Convex-test exercises handlers and transactions in its isolated implementation; it does not qualify the bundled backend binary. The production build covers the renderer, not an installed, signed or notarized desktop package. Vite reports a large main chunk (~1.54 MB minified / 466 kB gzip); bundle splitting remains a measured performance follow-up, not a correctness failure.

Before release, verify macOS and Windows packaged startup/shutdown, audio permission/device loss and complete recording/reprocess flow, Calendar overlap/permission failures, default-app file hand-off and recovery against copied workspace data. The existing runner fleet has no native Windows/macOS job, so Linux CI is not native acceptance.

Stop all backends using the source and destination during migration, including any nonstandard-port process. The TCP guard covers the documented port; it cannot prove no process anywhere has opened a directory. Retain the generated backup until the migrated workspace is inspected. First launch still supports attachment to a healthy local backend at the fixed port; deployment identity is not a new authentication boundary in this anonymous single-user design.

Editor recovery is profile-local and bounded by local-storage availability; it does not implement cross-device merge/conflict resolution. Recordings are in memory until the first successful storage upload, so a crash before upload can still lose audio. Schedule timezone remains a fixed offset and dependency cycles retain the existing warn-and-schedule policy. Large datasets can exceed Convex transaction limits because this local application intentionally uses whole-workspace reflow and inbound-reference scans; no multi-tenant/scaling claim is made.

The optional Reader and Knowledge services retain their separate deployment/data ownership. Backend function changes require a separate deliberate deployment to existing user data; rebuilding the renderer does not migrate or deploy those functions.
